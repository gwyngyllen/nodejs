# 十通道动态寻峰（2026-10-15纠正）

在 PyCharm 中运行 `monitor_channels.py`。每帧从 AQ6370E 读取完整 TRA 光谱、保存原始数据，并调用 `peak_search.py` 搜索谱峰和匹配通道。默认16个通道。通道数量、间距和“重新搜索通道”按钮均在顶部。最小间距不小于0.3 nm，默认0.30 nm。点击重新搜索后，下一帧按间距过滤后选设定数量的最强峰，按波长从短到长命名CH01至CHNN；后续维持这些通道身份，不随峰值功率排序变化而换号。候选不足时等待，不补造通道。每次重搜建立新编号段。不符合新下限的旧配置会迁移到0.30 nm并重新识别。这里的中心波长定义为峰顶位置，功率定义为峰值谱电平，不是积分功率。下文0.30 nm为历史调试记录，当前离线重算请使用 --peak-distance 0.30。

默认筛选：峰值不低于-40 dBm、局部突出度不低于6 dB、最小峰间距0.70 nm、突出度窗口±0.25 nm。V2匹配相对上一有效位置不超过±0.08 nm，不再限制累计漂移。失锁时至少80%通道共同位移一致、残差不超过0.025 nm，并连续3帧确认后才重捕获。接近半个通道间距或竞争编号解释时保留身份歧义和空值。参数在 `SearchConfig`，针对目前约1.14 nm峰间距，改变对象后需要复核。

状态分别为已跟踪、未检测到有效峰、通道失锁、重捕获确认中、通道身份歧义；不再统称“缺失”。程序重启时恢复上轮通道身份。若用户按“重新识别通道”并确认，则增加编号段`channel_epoch`，写独立配置，不能将不同编号段CH直接当同一物理通道。位移候选及重捕获过程保存在`channel_diagnostics.jsonl`。

用户还在AQ6370E自身WDM分析功能观察到大幅波长变化。这是仪器侧现象的佐证，不能单独证明相邻谱峰的身份对应或变化原因。

每轮文件：`spectrum_*.json.gz`（原始光谱）、`channel_peaks.csv`（逐帧逐通道）、`channel_status.json`（最新十通道状态）、`channel_config.json`（算法和初始通道）。`metrics.csv`和`report.html`仍是全谱最大峰的辅助统计，不能替代十通道结果。

离线重算：`python replay_channels.py --folder recordings/<本轮目录>`，输出十通道CSV、JSON及PDF/HTML报告。算法测试：`python -m unittest tests.test_peak_search -v`。日志统一保存在`tmp/logs`；报告工具在`scripts/reports`，诊断工具在`scripts/diagnostics`。

## 沟通错误说明

此前把“监控十个光谱通道的中心波长及峰值功率”误解成“读取十个固定波长点”。`bak/analyze_multi.py`、`bak/analyze_expanded.py`及相关固定点分析/报告脚本共11个已整体注释停用，并保留错误说明。旧固定点报告不得作为通道峰值或中心波长变化的结论。原始光谱可以用新算法重算。

## 验证及测量边界

测试覆盖亚采样波长漂移、峰高顺序反转、缺失及恢复、超门限漂移、无有效十峰、边界和非法输入。旧7700帧均已回放，260帧至少一个通道未匹配，保留missing。新程序已经真实连接AQ6370E并验证十通道CSV连续增长。

连续扫描读取X/Y不能证明每份快照是独立、同一轮完整扫描。RES未逐帧获取。峰位拟合不能独立证明仪器级精度或变化原因；重复帧不能算作独立扫描。

默认仪器地址：10.200.5.10:10001。运行中改变通道数量会在下一帧重建编号段，旧编号段与新编号段不能直接按CH编号对比。有效峰不足时等待识别，不补造通道。重启恢复最后已生效的通道数量。离线重分析可用 --channels N 指定数量；会话中途改过数量时应按编号段分别解读。


2026-10-16调试：最小峰间距默认改为0.30 nm并开放设置。用本机20261016_152908会话的187帧验证，旧0.70 nm每帧仅14候选峰；0.30 nm每帧28–29候选峰，最强16通道全部帧正常跟踪。此结果是实采光谱离线验证，不能替代新版本实机运行验证。旧会话恢复时仍显示保存的间距，请手动改为0.30并应用。离线重算可添加 --channels 16 --peak-distance 0.30。
